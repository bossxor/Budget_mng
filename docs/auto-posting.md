# 패턴 학습과 자동 반영 (v1.9.0)

기존 분류·거래 여부 학습은 유지한다. 새 확인 화면에 실제 표시한 추천과 사용자의 최종 답변을 별도로 저장해 패턴별 전환 조건을 계산한다. 기존 승인 자료만으로 과거 추천의 적중 여부를 추정하지 않는다.

## 전환

- 같은 패턴의 최근 확인 10건 중 제안 일치 9건 이상, 최근 5건 연속 수정 없음이면 한 번 자동 반영 전환을 제안한다. 이는 사용자가 정한 운영 기준이며 통계적 정확도 보장이 아니다.
- 조건 충족만으로 켜지지 않는다. 사용자가 범위를 확인하고 허용해야 새 알림부터 적용한다.
- 확실한 패턴은 현재 거래의 올바른 분류를 선택한 후 바로 지정할 수 있다. 거래 승인과 직접 지정은 동일한 DB 트랜잭션으로 저장한다.
- 설정 → 패턴 학습과 자동 반영에서 진행 상황, 지정 및 일시중지를 관리한다. 일시중지는 확인 건수를 지우지 않는다.

## 적용 범위와 복구

- 실제 출처 앱, 알림 제목, 출발/도착 통장 정보, 원래 입출금 방향, 상대 문구 및 숫자를 정규화한 전체 원문 해시가 일치해야 한다. 은행 앱 제목의 금액은 정규화하되 메신저·문자의 대화방/발신자 제목은 그대로 구분한다.
- 원문 해시를 확인할 수 없거나 통장·금액을 읽지 못한 경우, 환불·중복 의심·연결된 기존 거래에는 자동 반영하지 않는다. 거래 금액은 새 알림의 판독값을 유지한다.
- 자동 반영한 결과를 승인 정답으로 학습하거나 전환 확인 건수에 더하지 않는다. 모델 재생성·백업 이관 시에도 자동 반영 기록은 학습 정답에서 제외한다.
- 자동 반영 내역에는 표시와 되돌리기 동작이 있다. 수정·삭제·되돌리기는 해당 패턴을 중지한다. 연결된 이체를 되돌릴 때는 상대 기록의 연결 전 상태를 보존하며, 이후 변경이 있으면 무리하게 덮어쓰지 않는다.
- 백업에는 패턴·관찰·자동 반영 이력을 보존한다. 복원한 활성 패턴은 일시중지하고 사용자가 범위를 확인해 다시 켠다. 기존 백업에는 새 테이블이 없어도 복원할 수 있다.

## 데이터 변경

`auto_pattern`, `auto_observation` 테이블과 `tx.auto_applied_key`, `tx.auto_pair_before`를 추가한다. 기존 테이블과 승인 자료를 삭제하지 않는다. 중지 시 기존 자동 반영 거래를 소급 변경하지 않는다. 개별 거래의 되돌리기로 복구할 수 있다.
