# 알림 판독·확인 피드백 구현 상태

현재 작업은 v1.8.0 변경분이다. 기존 `notification-feedback.md`는 사용자 제안 원문으로 유지한다.

## 준비된 내부 처리

- 출처 패키지와 템플릿이 모두 일치할 때만 기존 확정 경로를 사용한다. 범용 파싱·추측·다른 앱이 흉내 낸 은행 템플릿은 `candidate`다.
- 후보와 거절 내역은 합계, 예산 원천, 위젯, 보고서, CSV, 저축·배분 계획, 정산에서 제외한다. 기존 `review`의 집계 방식은 유지한다.
- 원문과 출처를 확인하고 승인·수정·이유별 거절할 API를 추가했다. 판독과 분류 제안을 같은 카드에서 한 번에 승인할 수 있다.
- 확인한 거래만 분류 학습에 사용한다. 아니에요의 대화·광고·인증/예정/요청·기타는 별도의 거래 여부 판독 학습에 사용한다. 중복은 거래 자체가 거짓이 아니므로 부정 학습에서 제외한다.
- `NotificationClassifier`는 기존 로지스틱 회귀 엔진을 재사용하되 분류 학습 자료와 섞지 않는다. 같은 출처 앱의 제목·숫자를 정규화한 원문 조각을 입력으로 사용한다. 유사한 정답 최소 2건, 75% 이상 지지와 기존 점수·격차 기준을 충족할 때만 제안한다. 다른 앱의 같은 사람 이름에는 전파하지 않는다.
- 모델 결과는 제안만 바꾼다. 모델의 예측을 정답으로 저장하거나 자동 확정·자동 숨김하지 않는다. 대화방/앱 숨김은 사용자가 이유와 범위를 확인한 명시적 규칙만 적용한다.
- 등록 은행, 문자, 추가 등록한 금융 앱, 삼성카드 카카오 채널은 숨김 규칙에서 보호한다. 네이티브 수집 단계에서도 같은 정책을 검사하고 숨긴 대화는 원문 저장 전에 건너뛴다.
- 숨김 취소는 학습 표본과 규칙도 되돌린다. 삭제 표식으로 이전 백업 병합이 취소한 규칙을 되살리는 것을 방지한다. 복원 후 raw_id가 다른 원문을 가리키면 해시 검증으로 표시하지 않는다.
- 과거 범용 자동 거래 중 원문 일치가 확인되고 사용자의 승인·정산·분할·태그·쌍 이체가 없는 기록만 한 번 후보로 전환한다.

## 검증

로컬 검증 복사본에서 전체 Flutter 테스트 **106개 통과**, `flutter analyze lib test --no-pub` 문제 없음. Android `compileReleaseKotlin`, `compileReleaseJavaWithJavac` 통과.

새 회귀 검증은 메신저 오탐, 출처 위장, 승인 전 집계 제외, 수정·학습·되돌리기, 금융 출처 보호, 대화방 범위, 두 클래스 판독 학습, 상충 자료 보류, 중복 연결, 내 계좌 이체, 과거 이관, 백업 병합·원문 ID 충돌을 포함한다. 실제 사용자 알림 원문을 테스트에 넣지 않았다.

## 화면과 배포

사용자가 승인한 안내형 화면을 연결했다. 확인 카드에서 출처·원문·판독 금액·분류 추천·학습 근거를 확인하며 승인·수정·이유별 거절을 처리한다. 설정의 숨긴 알림에서 답변과 규칙을 되돌릴 수 있다. 기존 결과 알림의 검토 딥링크로 진입한다.

버전은 1.8.0+12이며 화면 회귀 검증 2개를 추가했다. APK 생성 후 기기 업데이트 설치와 Git 커밋·푸시, 새 릴리스 자산 검증 순서로 배포한다. 사용자 작성 notification-feedback.md는 원문으로 유지한다.
