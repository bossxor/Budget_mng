# 개인화 분류 학습

v1.7.0에 휴대폰 내부 학습 엔진과 승인 API, 사용자가 선택한 '한 건씩 안내' 승인 화면 및 '목록으로 한 번에' 통장 등록 화면을 포함한다.

## 동작

- `PersonalClassifier`는 승인 예제의 정답으로 다중 클래스 로지스틱 회귀를 재훈련한다. 거래 종류와 카테고리를 함께 예측한다.
- 입력은 상대 문구의 문자 조각, 출금/입금 방향, 출발/도착 계좌, 도착 통장 용도, 금액대, 일자 구간, 요일이다. 알림 원문과 이미 붙은 분류는 입력에 넣지 않는다.
- 유효 승인 이력 및 직접 입력에서 명시적으로 선택한 분류만 `learning_example`에 저장한다. 자동 생성 거래의 ok 상태나 모델 예측 자체는 승인 정답으로 취급하지 않는다.
- 학습 정답은 거래별 한 건으로 교체한다. 연결된 이체는 출금 측 한 건만 학습한다. 입력 특징 수정이나 거래 삭제 시 해당 예제를 제거한다.
- 과거 유효 승인 이력을 한 번 이관한다. 취소된 이력, 현재 분류와 다른 이력은 제외한다.
- 추천은 별도 저장하며 원래 거래를 바꾸지 않는다. 승인하면 거래 종류/분류와 학습 자료를 한 트랜잭션에서 갱신한다. 원래 분류 유지는 원래 카테고리가 있을 때만 학습 가능하다.
- 거래 또는 추천 내용이 바뀐 뒤 오래된 추천을 승인하면 거절한다. 분류 되돌리기는 학습 예제도 이전 상태로 복원한다.
- 학습 자료는 기존 암호화 백업에 포함한다. 가중치는 승인 자료에서 재생성하며 자료가 같으면 메모리 캐시를 재사용한다. 외부 통신이나 API 키는 필요하지 않다.
- 복원 시 같은 은행·계좌번호가 다른 통장 key로 들어와도 기존 통장에 거래·계획·학습 참조를 연결한다. 더 최근 승인 예제를 우선하며 현재 거래와 맞지 않는 오래된 예제는 학습하지 않는다.

## 보수적 추천 조건과 한계

- 최근 승인 자료 최대 500건으로 훈련한다. 추천 대상은 최근 90일의 미승인 알림 거래 최대 100건이다.
- 방향이 같은 유사 거래에서 같은 정답이 최소 2건이고 지지 비율 75% 이상이어야 추천한다. 모델 상대 점수와 1·2위 격차도 검사한다. 모르는 상대, 상충하는 승인, 환불/0원, 중복 의심은 무리하게 추천하지 않는다.
- 자료가 적어도 연결된 이체의 받는 통장 용도가 명확하면 그 용도로 확인을 요청한다. 근거에 학습 결과가 아님을 표시한다.
- 모델 점수는 실측 정확도가 아니므로 UI에 정확도 %로 표시하지 않는다. 자동 반영은 구현하지 않았다. 추후 자동화에는 별도의 사전 예측/사후 승인 평가와 사용자 설정이 필요하다.
- 새로운 알림 형식의 금액/계좌 추출은 기존 파서가 담당한다. 이 모델은 추출된 거래를 분류하며 파서 코드를 스스로 바꾸지 않는다.
- 등록한 은행과 전체 계좌번호가 일치하면 기존 통장 key로 수집하고, 상대 계좌가 내 통장이면 받는/보내는 통장을 식별한다. 마스킹된 번호나 끝자리만으로는 자동 연결하지 않는다. 받는 통장의 용도가 명확하면 첫 이체부터 해당 목적의 확인을 요청할 수 있다.

## 검증

`test/personal_learning_test.dart`에서 문구 변형과 다중 분류, 승인 전 거래 보존, 수정/되돌리기, 학습 중복 방지, 오래된 추천 거절, 알림 집계, 재시작/백업/초기화를 검증한다. 기존 알림/이체/정산/저축 회귀 테스트도 함께 사용한다.

`test/personal_review_test.dart`와 `test/account_registration_ui_test.dart`에서 실제 버튼으로 승인·수정·되돌리기, 여러 통장 등록 및 기존 통장 정보 추가를 검증한다. `test/account_registry_test.dart`는 계좌 식별·중복 방지·다른 기기 백업 병합을 검증한다.
